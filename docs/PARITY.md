# Parity with the Go reference

Every case runs the Rust binary and compares it with what the Go reference (`eat-pray-ai/yutu@bbf38cb`, built by `ref/build.sh`) did for the same input: the HTTP requests it sent (method, path, query, body by value), stdout, stderr and the exit code, byte for byte after the normalizations below. Generated by `parity/report.py`.

## Normalizations

Only these, each one function in `parity/diff.py`:

- `split_part`: Splits comma-joined `part` values, since Go sends `part` joined or repeated.
- `mask_boundary`: Replaces the random multipart boundary with a fixed token.
- `multipart_parts`: Splits a multipart body into parts, decoding the JSON part by value.
- `body_value`: Compares JSON bodies by value instead of by bytes.
- `mask_time`: Replaces slog `time=` stamps in stderr with a fixed token.
- `mask_port`: Replaces the recorder's random loopback port with a fixed token.
- `mcp_by_value`: Parses each JSON-RPC reply line so MCP stdout compares by value, not key order.

## Known Go defects reproduced on purpose

Go is the oracle, so these behave as Go does. They are candidates for fixes after cutover.

- **playlist update, playlistItem update (CLI)**: never set MaxResults, so the lookup sends no request and the command fails with "failed to get ..."
- **channel update, comment update (CLI)**: the same: the lookup paginates with MaxResults 0 and always fails
- **comment markAsSpam / setModerationStatus**: print the input struct itself, including "confirmed":false
- **liveBroadcast bind**: prints the response id and an empty stream id when --streamId is unset
- **agent skill toolset**: list_skills is empty and load_skill finds nothing, because yutu's embed nests the skill one directory deeper than ADK reads; `Skills::embedded()` in crates/yutu-agent is the ready fix
- **several list tables**: Go dereferences nil nested fields and would crash; the port prints empty cells instead (never reachable with real API responses)
